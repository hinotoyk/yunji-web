# 云迹 · 数据血缘树（每个字段怎么得来的）

> 以最终产物 `data/crops.json`（每匹马一条记录）为根，向下展开每个字段的**来源 → 处理 → 去向**。
> 三个问题：① 数据从哪里来（叶子的源）② 怎么处理到下一步（→后的处理）③ 最终是直接获取还是交叉校验（标注在叶子旁）。
> 图例：`源 ──处理──▶ 值`；`[直取]`=直接获取  `[校验]`=经交叉校验/比对  `[人工]`=用户录入/裁决  `[计算]`=构建时自动计算

## 一句话回答三个问题

1. **从哪来**：netkeiba（基础/血统/成绩）、JBIS（血统兜底）、**Google Sheets 台账（比赛权威源）**、用户（人工字段/未来图片）。
2. **怎么处理**：每层只认契约 —— 采集（抓取+风控）→ 校验清洗 → 交叉比对 → 合并计算；规范化/推导/汇总都在构建时完成，源值不动。
3. **最终是直接获取还是交叉校验**：
   - 基础信息/血统 = **直接获取**（netkeiba 主/JBIS 辅）
   - 比赛记录 = **当前直接取台账**，netkeiba 成绩**只作旁路监察**（比对不进产物）；**未来**：比对差异经你确认进 overrides 后，**落盘的是交叉校验+人工裁决的结果**
   - stats/venue_type/race_class = **计算派生**；人工字段/未来图片 = **人工**（overrides 保护）
