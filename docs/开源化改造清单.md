# 开源化改造清单（yunji-web → 通用「种马应援站」模板）

> **本文档是什么**：把 yunji-web 从「个人维护的单站」改造成「任何人都能 clone → 改配置 → 部署自己应援种马」的开源项目的**执行清单**。
> 2026-11-11 审计产出，同日按用户逐项决策修订（决策见 §1.1 总表）。协议已定 **MIT（代码）+ 独立数据声明**。
> 每条都标了**文件:行号**证据与**验收方式**；全部落地后本文可归档（规则沉淀进 README / AGENTS.md / `config` 字段契约）。

## 1.2 缺口明细与处理方案

### #1 产驹生年 `YEARS_DEFAULT` → 配置

| 项 | 内容 |
|---|---|
| 现状 | `scripts/basic/build_registry.py:25`、`scripts/basic/fetch_nk_id.py:24` 各自 `YEARS_DEFAULT = ["2023", "2024"]` |
| 不改的后果 | 换种马后要么建档 0 匹、要么漏整代；**不报错**，是最难查的一类坑 |
| 设计 | `config/sire.json` 的 `sire` 段加 `"progeny_years": [2023, 2024]`，语义 = **只抓列出的生年**。没到时间的年份（未出生 / 未登记 / 尚无产驹）**不要写进来**即可，天然满足「没到时间不拉」 |
| 单一出处 | `scripts/core/sire_config.py` 加访问器 `progeny_years()`（与 `jbis_id()` / `studbook_name()` 同层）；两处 `YEARS_DEFAULT` 改为 `sire_config.progeny_years()` |
| 校验（不做静默降级） | 非整数 / 年份 < 1980 / > 当前年 → `sys.exit` 明确报错并指向字段契约；**> 当前年给 warning 并跳过该年**（防手滑写 2027 白跑整轮） |
| CLI 覆盖 | `--year 2023,2025` 临时覆盖仍保留（不入配置） |
| 迁移 | yunji 现值 `[2023, 2024]` 写进配置；⚠ kzn 是 `[2017..2025]`，回灌时**不要反向覆盖** |
| 验收 | 改配置为 `[2024]` → `build_registry.py --print-urls`（不联网）只输出 2024 的 URL；配置写 `[2027]` → warning + 跳过；写 `["abc"]` → 报错退出 |

```jsonc
"progeny_years": [2023, 2024]   // 只抓这些生年；未出生/未登记/尚无产驹的年份不要写
```

### #2 `GH_REPO` 是干嘛的（先解释，再配置化）

**它是「本站仓库地址」常量，编辑台全套 GitHub API 都靠它定位目标仓库**（`front/public/yj-util.js:161`，2026-11-11 §190 收口为单一出处）：

1. **PAT 校验**：`GET /repos/<GH_REPO>`，200 才算「这把令牌属于本站」—— 双站防串的关键（拿 A 站 PAT 解不开 B 站编辑页）。
2. **编辑台提交**：读文件树、建 blob、拼 tree、建 commit、更新 ref 共 20+ 处 `/repos/<GH_REPO>/...`（`editor.js:383-817`）、commit 链接、Actions run 查询。
3. **编辑门禁**：未解锁时整页换成解锁卡片，文案里显示仓库名（`yj-edit-gate.js:42`）。

**fork 后忘改会怎样**：编辑台永久打不开（403），提示还是「该 PAT 无权访问本站仓库 **hinotoyk/yunji-web**」——既误导使用者，也把我的仓库名暴露在每个 fork 上。**不会泄露 token**（令牌只发给 GitHub），也不会让别人写我的仓库（权限由 GitHub 按令牌判定）。

**处理**：`config/sire.json` 的 `site` 段加 `"repo": "owner/repo"` → 注入 `YJ_SITE.repo` → `YJ.util.GH_REPO` 改读配置。**空值 = `editUnlocked()` 恒 false、侧栏编辑组不注入、PAT 对话框不出现（fail-closed）**，build 时打印「未配置 site.repo → 编辑台关闭」。

### #3 / #4 访问统计：不想让 fork 给我的后台加数

**先说结论：现在的风险比想象的低，但确实有唯一一条漏洞路径。**

- 已有保护：`yj-visit.js:30` 首行域名门控 —— `site.domains` 白名单不含当前 host 就 `return`，**统计脚本连加载都不加载**。fork 默认 `domains: []` 或填自己域名 → 不会计入我的 GoatCounter。
- 唯一漏洞：fork 者按换站步骤把自己的域名填进 `domains`（这是必做的），但 `GC_CODE = 'yunji'` 写死 → 他的访客数量直接进我的后台。这就是要堵的那条。

**处理（`site.analytics` 配置 + 三态）**：

```jsonc
"site": {
  "domains": ["自己的域名"],
  "analytics": { "goatcounter": "", "vercount": false }   // 两项都空 = 完全静默
}
```

- `goatcounter` 为空 → 不注入 `count.js`、不拉 `counter/TOTAL.json`、页脚「总访问」节点**根本不进 DOM**；
- `vercount` 缺省 `false` → 不注入 `cn.vercount.one`（那是第三方公用计数，不归属我，但 fork 也没必要白送一次第三方请求）；
- `domains` 非空但 `analytics` 未配 → **build 警告**：「已开域名白名单但统计未配置，统计将保持关闭」；
- `index.html:128` 的 `<a href="https://yunji.goatcounter.com">` 从静态 HTML 删除，改由 `yj-visit.js` 取数成功后创建/填 href —— 无配置时页面上**不存在**指向我后台的链接。

> 附带收益：这一改同时满足「本地/他人域名不计数」的原口径，且不需要 fork 者理解 GoatCounter 是什么。

### #5 友链 `SITES` → JSON 配置

- 现状：`front/public/friend-links.js:34-56` 写死四站（含 `desc: "コントレイル 产驹档案"`），四站共用同一份文件。
- 处理：新增 `config/friend-links.json`（数组，字段 = id/logo/color/name/sub/url/desc）→ `gen-site-config.mjs` 注入 `window.YJ_FRIENDS`；`friend-links.js` 优先读 `YJ_FRIENDS`，**缺省 `[]` = 挂载点保持空白**（脚本缺失/未配置都零痕迹，与原设计一致）。
- 兼容：jbis / rc 两站不跑本仓构建，仍走各自的注入方式；脚本保留内置注册表作**显式 fallback**（仅当页面设了 `data-friends-legacy` 才用），避免这两个站升级即白屏。
- 验收：`config/friend-links.json` 置 `[]` → 侧栏无「友情档案」分组，`dist` 内无 `hinotoyk.github.io` 字样。

### #6 `data-site="yunji"`：默认从 `site.id` 派生

你的要求是「必须要让他们改」，但**手改项正是漏改的来源**：漏了的结果是侧栏把自己也列出来（点自己跳自己），而且不会报错。所以做成「默认派生 + 可覆盖」：

- `index.html` 挂载点保留 `data-site` 属性，但**值为空时读 `window.YJ_SITE.id`**；
- `gen-site-config.mjs` 把 `data-site=""` 直接替换为站点 id（`{{YJ_SITE_ID}}` 占位符），所以线上 HTML 里看到的就是真实 id，行为与手改完全一致；
- 显式写死的值仍优先（jbis/rc 等非模板站行为不变）。

### #7 PAT 提示文案里的仓库名：随配置变

| 位置 | 现状 | 处理 |
|---|---|---|
| `front/index.html:147` | 静态文本「仅 hinotoyk/yunji-web · Contents 读写」 | 新增 `{{YJ_SITE_REPO}}` 占位符（复用现有注入机制，不新增管线） |
| `front/public/editor.js:2723` | 内联 HTML 拼「yunji-web」 | 改用 `U.GH_REPO` 变量拼接（`editor.js:25` 已取该常量） |
| `front/public/yj-edit-gate.js:42` | 已用 `U.GH_REPO` | 无需改，自动跟随 |

`site.repo` 为空时，整段提示替换为「本站未配置编辑仓库（`site.repo`），编辑功能已关闭」，且入口不渲染 —— **不会出现「请粘贴 hinotoyk/yunji-web 的 PAT」这种把用户往错误仓库引的文案**。

### #10 管线超时：只提醒，不自动算

- `run_update.py` / `run_full_test.py` 启动时打印当前超时值与已有马数，马数 > 400 时追加一行提示「种马产驹较多，全量重建若被掐断请调大超时」。
- README 换站清单加一条：「产驹 > 400 匹的种马，先把 `run_update.py` 的超时改大（kzn ~1221 匹用 28800s）」。
- **不按马数自动计算**：抓取耗时受网络/风控影响，自动算出来的值会给人虚假安全感。

## 2. 协议方案（已定：MIT + 数据声明）

### 2.1 为什么必须拆两层

- **代码**：你写的，可授权 → MIT。
- **数据**：`data/` 抓取自 JBIS / netkeiba / studbook.jp / 台账，`data/photos/` 17 张 webp 是赛事照片 → **版权不在你手上，不能用 MIT 授权**，只能声明来源与使用边界。
- **商标**：MIT 不含商标。「云迹 / 云崽档案 / 雲 logo」不应被 fork 站沿用 → README 明写。

### 2.2 落地文件

- `LICENSE`：标准 MIT 全文，版权行 `Copyright (c) 2026 hinotoyk`。
- `NOTICE`：四件事 —— ① 数据抓取自 JBIS/netkeiba/studbook，版权归原站，仅个人查阅存档；② 管线内置 `DOMAIN_SLEEP` 风控、遵守访问频率，但**不构成再分发授权**；③ `data/photos/` 版权归摄影者/赛事方，权利人可经 Issue 要求移除；④ fork 者自行承担数据使用责任，商用须自行取得授权。
- `README.md` 顶部「License」小节：代码 MIT / 数据见 NOTICE / 商标不随授权。

### 2.3 不选方案（留档防反复讨论）

- **AGPL-3.0**：纯静态站无「网络服务提供」边界，约束力弱且提高 fork 门槛。
- **PolyForm Noncommercial**：若后续担心商用可换此项，改动仅一个文件。
- **CC BY-NC 4.0 覆盖全部**：不适合代码，只适合文档与图片。
