# 子项目复制与同步指南（yunji-web → kzn-web 等）

> **本文档是什么**：yunji-web（云迹 · コントレイル产驹档案）作为**模板站/主项目**，会被复制派生出「同业务、不同应援对象」的子项目站（现有：kzn-web = 絆 · キズナ产驹档案）。本文写清两件事：
> **A. 如何从 yunji-web 复制出一个新子项目**；**B. yunji-web 更新后如何同步到子项目**。
> 所有 agent 在执行复制/同步前必须通读本文，尤其是 §1 的「品牌保留清单」——同步事故几乎都出在「整拷时把子项目个性冲掉」或「数据耦合断言在另一仓假失败」。

---

## 0. 两仓关系与现状

- **yunji-web** = 主项目。页面结构、业务逻辑、数据管线、构建链全部以它为准；改造在 yunji 发生，再同步到子项目。
- **kzn-web** = 第一个子项目（`github.com/hinotoyk/kzn-web`）。业务与 yunji **完全同构**，差异只有站点身份（应援的种马、站名/logo/域名、统计口径）。
- ⚠ 两仓**不共享 git 历史**（各自独立 init），**不能 `git merge`**。同步 = 按本文规程做文件级操作。
- ⚠ 同步方向以 **yunji → kzn** 为主；kzn 侧偶有改进会「回灌」yunji（历史先例：§138 firstRow、冒烟泛化断言）。同步前先看 §4 回灌清单，**不要把 kzn 已回灌/领先的部分用旧版覆盖回去**。

## 2. A · 从零复制一个新子项目

前提：本机有 Node ≥18、Python ≥3.10（含 fontTools+brotli 可选，缺了字体自动降级并警告）。

1. **复制骨架**：拷贝整个 yunji-web 目录，**排除** `.git/`、`node_modules/`、`dist/`、`data/`、`tests/`、`test-logs/`。data 由管线自建；tests 是 yunji 的探索稿，子项目不需要。
2. **初始化仓库**：`git init` + 新 GitHub 仓（如 `xxx-web`）+ 首次 commit。`.gitignore`/`.gitattributes` 原样带过去。
3. **站点身份改造**（逐项过 §1 清单）：
   - `config/sire.json`：改 sire 档案（name_ja/name_en/jbis_id/netkeiba_id/studbook/wins）与 `site` 块（`id` ←⚠ 站点存储前缀的源头，必须唯一；name/subtitle/tagline/logo/domains/ledger）。
   - 全局替换品牌头（云迹→新站名）、favicon.svg、`wrangler.jsonc`/`package.json` name、README/docs 重写、workflows 里的仓库名。
   - 若换主色：`front/tailwind.config.js` 的 `primary/chart-*` 语义色（注意 §157+ 图表内嵌 hex 与主题 token 的对齐注释）。
4. **数据初始化**：`python run_update.py --init`（⚠ 会删空/重建 `data/`，先读 `docs/TESTING.md` §4.3）→ 再跑 `python scripts/datechart/build_datechart.py`、`scripts/stats/build_stats.py`、`scripts/timeline/build_timeline.py` 生成三个预计算产物。
5. **构建与验证**：`cd front && npm install && npm run build` → 核对 dist（§3 第 7 步同款清单）→ 四段冒烟全绿。
6. **部署**：GitHub Pages（`.github/workflows/deploy.yml` push main 自动构建发布）或 Cloudflare Pages（`wrangler.jsonc`）。`site.domains` 填正式域名后访问统计自动启用（先注册 GoatCounter 并改 `yj-visit.js` 的 `GC_CODE`）。
7. **建子项目文档**：`docs/UI优化记录.md`（自起 § 编号，同步条目标注「同步 yunji §N」映射）、`AGENTS.md`（从 yunji 版改站点名，规则同构）。

## 3. B · 日常同步流程（yunji 更新 → kzn）

1. **确定同步区间**：看 yunji `docs/UI优化记录.md` 最新 §，对照 kzn 侧记录的「已同步到 yunji §N」。跨多节时可整批做（先例：§117 = yunji §139–§169 一次同步）。
2. **diff 盘点**（在两仓父目录执行）：
   ```bash
   diff -rqs --strip-trailing-cr yunji-web/front kzn-web/front | grep -v identical
   ```
   ⚠ **必须带 `--strip-trailing-cr`**：yunji 工作区是 CRLF（autocrlf=true）、kzn 是 LF，不带会全量假差异。
3. **分类套用**：
   - **整拷**（转 LF 后覆盖）：全部滞后/新增的 `front/pages/*.html|css`、`front/public/*.js`、`front/index.html`、`front/tailwind.config.js`、`front/scripts/*`、后端 `scripts/**` 中有功能差异的文件。新文件直接拷（如 §141 的五页 CSS、§145 的 echarts.line.min.js、§156 的 lightbox.js）。
   - **拷后适配**：§1 清单中标「拷贝后替换/适配」的项（品牌头、SRK 注释、统计口径、vite 注释）。
   - **不动**：§1 清单标「永不动」的项。
   - `scripts/**` 逐个 `diff` 判断：**仅品牌注释/UA/年份默认值差异 → 不动**；功能差异 → 整拷。
4. **数据契约检查**：若本次同步动了 `scripts/*/build_*.py` 或 `docs/SCHEMA.md`（例：§159/§165 datechart 21→33 键），在 kzn 重跑对应 build（`python scripts/datechart/build_datechart.py` 等）+ 把 SCHEMA.md 契约段同步过来。stats.json 重跑幂等（内容无变化会跳过写入）。
5. **verify 脚本同步**：三段冒烟（datechart/stats/drill）整拷 yunji 新版后，**逐条排查数据耦合断言**（见下方红线）。verify_result.cjs 三态闭合是数据无关的，直接对账即可。
6. **构建**：`cd front && npm install && npm run build`。
7. **dist 核对**（编译期框架最大坑：改了类没编译=没生效）：
   - `dist/assets/theme-*.css` 含新类、新增页面 CSS 五档（stats-/datechart-/races-/leaderboard-/timeline-*）在；
   - `dist/data/basic.json`、`stats.json`、`datechart.json`、`races-bundle.json` 存在且为新契约；
   - `dist/site-config.js` 注入的是 **kzn** 品牌（grep 絆/kzn）；新增 public JS（lightbox 等）进了 dist 根。
8. **五段冒烟全绿**：`node scripts/datechart/verify_datechart.cjs && node scripts/stats/verify_stats.cjs && node scripts/races/verify_drill.cjs && node scripts/races/verify_result.cjs && node scripts/timeline/verify_sire_wins.cjs`。
   ⚠ 子项目换种马后必须 `python scripts/timeline/sync_sire_wins.py`（抓种马本人成绩页派生 `data/sire_wins.json`）再 `build_timeline.py`；`config/sire.json` 的 `sire.wins` 只是兜底，改了不重跑派生会被 verify_sire_wins 报漂移（yunji §172）。
9. **记录**：kzn `docs/UI优化记录.md` 追加新 §（映射 yunji § 区间、同步方式、冒烟适配点、验证结果）；`TESTING.md` 断言计数按实际跑出的数字更新（断言数随数据量浮动，以实测为准）。commit 仅在用户要求时执行（AGENTS.md Git 约定）。

### 冒烟断言改写的红线（数据耦合 → 一律派生式）

verify 脚本里任何**具体值**（马名、世代名、年份数、场地、条数、「哪个档为空」）都会在另一份数据上假失败。同步时把 yunji 版里这些硬编码改成从产物派生：

- 世代全集/系列数/图例 ← `stats.json` 的 `by_venue[*].scopes.all.curve` 的 gen 去重排序（先例：yunji 写死「2023/2024 两世代」，kzn 八世代直接爆）。
- 目标样本马（如「带生产国尾缀的马」）← 按 SUF_RE 从产物现找，断言消息里打印源值。
- 「仍有空档」类存在性断言 ← 改为「n 与源数据重算一致」。
- 页面交互注意事项：datechart 的 vseg 是**开关切换**（已激活再点会切掉）、明细分页状态 `st.dp` 跨渲染持久化（翻页查找前先归 1）、month 模式面板无年份直选（用 data-nav 逐月走）、PC 100 条/页 mb 10 条/页（目标行可能不在第一页）、races.html 删除胶囊走 `renderFilters` 整体重建（不走 refreshDimUI 局部注入）。

## 5. 教训速查（历史实测，同步前扫一眼）

- 行尾符污染 diff：两仓 EOL 不同，diff 一律 `--strip-trailing-cr`，拷贝统一转 LF。
- 数据耦合断言是同步最大假失败源（§3 红线）。
- 字体子集不拷贝，构建期现算；`front/assets/fonts` 不进同步清单。
- `site.domains` 空 = 统计关闭是 kzn 既定口径，别把 yunji 的域名写死进去。
- 每次改完必 `npm run build` + dist 核对 + 冒烟全绿，才算同步完成。
- **托管平台会剥 `.html`**：Cloudflare Pages 把 `/pages/x.html` **307** 成 `/pages/x`（GitHub Pages 不剥），所以任何用 `location.pathname` 与 `*.html` 做比对的代码，都必须先经 `pageKey()` 剥尾部 `.html` 再比（yunji §173 / kzn §117.4，踩过一次：线上侧栏高亮全灭）。新子项目若上 CF Pages，这处归一必须跟着带；本地验证用 `tests/_tmp_cfstrip/serve_cf.py`（模拟 307）+ 无头浏览器 dump `data-on` 对账，别只看本地静态服务器——**本地不剥扩展名，永远测不出这个坑**。
- 未经用户指示不 `git commit`/`git push`（两仓 AGENTS.md 同约定）。
