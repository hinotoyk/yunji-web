## 3. 模块 1 · 搜索栏（基本信息 · PROFILE 顶部）

### 3.1 背景与需求

基本信息页顶部搜索栏（`selector.js` 注入）原仅支持**四种名字**（日文名 / 欧字名 / 自译名 / 香港名）与 ID 检索，视觉普通、信息密度一般。用户诉求：默认可搜四种名字，并**额外支持母名 / 马主 / 调教师 / 生产牧场**；样式**简约、高信息密度**（契合主题：青绿 × shadcn Neutral）；只改基本信息页与搜索栏，不动其它模块。

### 3.2 选定与理由（思路）

对比「分段搜索 / 多字段筛选栏」后拍板**智能单框**：一个输入框一次匹配全部 8 类字段，最省空间、最快速，配合下拉行的字段命中标注，兼顾速度与信息密度，最贴合"高信息密度 + 简约"目标。

### 3.3 打磨迭代

1. **占位符直接提醒**：`日文名 · 英文名 · 港译名 · 自译名 · 母名 · 马主 · 调教师 · 生产牧场`，一眼看到可搜范围。
2. **下拉展示多名字**：结果行展示该马全部名字，主名加粗、其余弱化。
3. **性别用原生 牡/牝/セン**：不再翻译成 公/母/阉。
4. **名字类型区分（定稿）**：小字标签方案不可读 → 改为**彩色色块包着字体**：青绿=日文名 / 蓝=英文名 / 橙=港译名 / 紫=自译名；中间缺口显示灰块 `—`，结尾缺失省略。
5. **性别徽章配色**：`♂ 牡` `#C9EFFE` / `♀ 牝` `#FFDBD5` / `⚲ セン` `#EFEFEF`（文字加深保证可读）。
6. **整体视觉打磨**：输入框 hover/聚焦态、下拉圆角投影、选中行左侧青色竖条、下拉顶部"匹配 N 匹"计数条。
7. **计数徽章入框**：输入框右侧实时计数徽章（空态=总马数，输入=命中数青色高亮）。
8. **术语统一**：全站名字术语统一为「日文名 / 英文名 / 港译名 / 自译名」。
9. **滚动条 / 动画 / 移动端**：下拉细滚动条、150ms 淡入（尊重 `prefers-reduced-motion`）、≤768px 收紧。
10. **选中回填主名**：选完回填该马日文主名；再次点击输入框自动清空重搜；去掉 `✓ 已选` 徽章与计数，界面更干净。

### 3.4 最终落地

- **合并文件**：
  - `pages/selector.js` — 搜索组件主体（结构 + 样式注入 + 检索逻辑 + 键盘导航 + 选中回填）。
  - `pages/profile.html` — `<div id="selector"></div>` + `YJ.selector.init({el, base, onSelect})`，渲染逻辑不动。
- **实现要点**：
  1. **检索字段**（大小写不敏感子串匹配）：名字 `馬名 / 欧字馬名 / 自译馬名 / 香港馬名` + 附加 `母名 / 馬主 / 調教師 / 生産牧場` + 兼容 `id`。
  2. **下拉行**：名字彩色色块（`.nblock.jp/.en/.hk/.zh`，主名 `.main` 加粗，缺口灰块 `—`）+ 右侧性别徽章 + 出生年；命中非名字字段显示青色字段胶囊 + 命中值副行。
  3. **计数徽章** `.cnt`：空态总马数、输入命中数青色高亮；**选中回填**：回填日文主名、再次点击清空重搜。
  4. **键盘导航**：`↑`/`↓` 高亮、`Enter` 确认、`Esc` 关闭。
  5. **动效/可访问性**：150ms 淡入（尊重 reduced-motion）、细滚动条、≤768px 收紧。
- **样式**：全部由 `selector.js` 注入（`#yj-sel-css`），沿用 `theme.css` 变量（性别/名字色块为指定色值，已在本节记录）。

### 3.5 状态

✅ **已完成**（已合并进 `pages/profile.html` + `pages/selector.js`，本模块封版）。

## 4. 模块 2 · 字体（全局排版）

### 4.1 背景与需求

用户反馈**当前字体太丑、看不清**。原 `theme.css` 是纯系统字体栈，问题：Windows 中文落到微软雅黑小字号发虚发闷、数字未全站等宽、字号过小易糊。需求：一套中/日/英混排 + 数字友好的字体方案。

### 4.2 选定与理由（思路）

关键约束：**中文/日文全量 Web 字体单字重 5~10MB**，全量引入必然拖慢。最终方案分两层：

- **拉丁/数字**：单文件可变字体 **Geist**（~29KB 覆盖全字重），本地自托管、离线可用、OFL 开源。
- **中文/日文**：默认**本地自托管思源黑体 Noto Sans SC**（101 子集按需加载）；苹方 / 微软雅黑仅作系统回退、不打包分发（授权合规）。
- 全站开启 `tabular-nums` 数字等宽，让成绩/距离/日期/赔率数字对齐。

### 4.3 打磨迭代

1. **@font-face 自托管**：Geist latin 子集 woff2（29,400B，`wOF2` magic 校验），`font-weight:100 900` 一个文件覆盖全字重，`font-display:swap`。
2. **全站字体栈**：`'Noto Sans SC','Noto Sans CJK SC','Geist','PingFang SC','Microsoft YaHei',…` —— 中文走思源、拉丁/数字走 Geist。
3. **可读性小包**：`line-height`、`-webkit-font-smoothing:antialiased`、`text-rendering:optimizeLegibility`、全站 `font-variant-numeric:tabular-nums`。
4. **字号上调**：表格 13→13.5、表头 11→11.5、字段标签 10.5→11、血统简约版 meta 7→8、行高 15→17px。
5. **界面文字放大（用户点名）**：节标题 11px 45%灰 → **14px 深色 + 字重700 + 左侧青色竖条**；表头 12.5px、字段标签 12px、KPI 标签 12.5px、徽章 12px 用深色；次要文字统一由浅灰提到深灰保证对比度。
6. **授权合规确认**：Geist / 思源黑体 = SIL OFL 开源免费商用；苹方 / 微软雅黑 = 系统内置仅回退、不打包分发。
7. **用户拍板定稿**（试衣间辅助拍板）：
   ```css
   body{
     font-family:'Noto Sans SC','Noto Sans CJK SC','Geist','PingFang SC','Microsoft YaHei',sans-serif;
     font-size:16px; line-height:1.40; letter-spacing:0.10px;
     font-variant-numeric:tabular-nums; -webkit-font-smoothing:antialiased;
   }
   ```
   默认中文思源黑体 + Geist 拉丁/数字回退；回填 `theme.css`，接入本地 `noto-sc.css`。

### 4.4 最终落地

- **合并文件**：
  - `pages/theme.css` — `@import` 本地 `noto-sc.css` + `@font-face`（Geist）+ 全局 body 字体栈/字号/行高/字距/等宽 + 表格/表头/标签字号上调。
  - `pages/fonts/noto-sc.css` + `noto-sc/`（101 子集）+ `pages/fonts/geist-latin.woff2` — 全部本地自托管。
  - `pages/pedigree.js` — 血统简约版字号/行高微调。
- **实现要点**：`@import` 与 `@font-face` 用相对路径，各页面经 `theme.css` 自动继承，无需每页改；全站 `tabular-nums` 数字对齐。
- **样式**：字体全本地自托管 + 系统回退，无外部 CDN 依赖，离线可用。

### 4.5 当前字体资产（`pages/fonts/`，共 ~4.4MB）

| 资产 | 大小 | 用途 |
|---|---|---|
| `geist-latin.woff2` | 29KB | 拉丁/数字回退（body 栈第 3 位） |
| `noto-sc.css` + `noto-sc/`（101 子集） | ~4.4MB | **思源黑体 Noto Sans SC**（默认中文，unicode-range 分段按需加载） |

### 4.6 状态

✅ **已完成 + 用户拍板封版**（思源黑体 16px/1.40/0.10px 已回填 `theme.css`）。

## 5. 模块 3 · 基本信息页两栏布局（常驻过滤搜索 + 详情 + 总览）

### 5.1 背景与需求

用户提供布局草稿《赛马页面布局草稿_三栏三段式.md》：基本信息页按**左中右三栏**组织——左=目录、中=常驻过滤式搜索栏、右=详情；详情区内部三段（图片+基本信息+血统 / 数据概览 / 比赛记录）。逐轮明确：中间过滤搜索**直接复用现有搜索框**（`selector.js`）做成常驻可见列表；**mb 端不做三栏**（窄屏堆叠单列）；布局避免「表格框架感」，用留白/卡片/圆角/字体层级区分区域。

### 5.2 选定与理由（思路）

- 初稿三栏中**左栏「赛马目录」与外壳侧边栏已有导航重复**（用户澄清：目录=外壳侧边栏，页内重复造目录是误解）→ **页内两栏**：左=常驻过滤搜索（400px）+ 右=详情；左栏目录由外壳侧边栏承担。
- 搜索列复用 `selector.js` 并新增 **`persistent` 常驻模式**（下拉始终可见、随容器高度伸缩、加载即展示全部列表），不改默认弹层行为（races / pedigree 页不受影响）。
- 两栏满屏、各栏独立滚动、常驻不随选中消失；<1024px 自动堆叠单列。

### 5.3 打磨迭代

1. **常驻列表模式**：`selector.js` 新增 `persistent: true` —— 下拉改常驻列表，保留输入即过滤、键盘选择、计数徽章。
2. **窄屏堆叠**：<1024px `max-lg:block` 堆叠单列；常驻列表限高 `max-h-[45vh]` 滚动。
3. **两侧留白（实测定位）**：用户反馈「两边好空」→ 无头浏览器实测原 `max-w-[1500px] mx-auto` 宽屏左右空 100px+ → **去掉限宽铺满内容区**。
4. **未选马空白**：右侧详情列空 → 新增**数据总览面板**（统计卡片 + 引导文案），`min-h-full` 撑满整列。
5. **总览分组 + 文案**：统计卡片分三类 —— 基础（`收录产驹总数`/`比赛记录`）、出生年（`2023 年生`/`2024 年生`）、性别（`牡马`/`牝马`/`骟马`）；隐藏「最新建档 · RECENT」。
6. **搜索列加宽**：320px → **400px**（用户要求 1.25 倍）。
7. **性别统计 bug**：数据中骟马字段为 `セン`，初版按 `セ` 查找漏计 → **`セ`/`セン` 归一化**，两者都计入骟马。
8. **站点名**：`Contrail` → `コントレイル`（侧边栏副标题 + 页标题 + 总览面板）。

## 7. 模块 4 · 马匹详情「上中下」一体式布局（无卡片 / 无分割线）

### 7.1 背景与需求

用户提供布局草稿：右侧「详情」区为**三段式纵向布局**——第一段=图片+基本信息+血统、第二段=数据概览、第三段=比赛记录。草稿反复强调：**不要照搬线框，用留白、间距、背景层次、字体层级等方式区分区域**。用户拍板两点硬性要求：**最反感用「明显的卡片」或「分割线」做布局**（要一体性）；**mb 端也要同步上中下布局**，但**左中右（搜索列 + 详情列）布局不能改**。

### 7.2 选定与理由（思路）

## 10. 设备判定统一入口（YJ.device）+ 断点切换实时重渲染

### 10.1 背景与需求

pc / mb 判定此前散落多处且标准不一：CSS 层用 Tailwind `md:`（768px）单断点，但 JS 层 `races.html` 自写 `isMb()`（768px）、`profile.html` 用 `innerWidth>=1024`（常驻列表）。实测「桌面宽度先渲染出 PC 表格 → 切到手机」时，CSS 实时响应、但 JS 渲染的表格冻结为 PC 样式。用户诉求：**统一一个入口判定设备，pc 就走 pc 界面、mb 就走 mb 界面**，后续功能一律调用它。

### 10.2 选定与理由（思路）

- 新建共享脚本 `public/device.js`，暴露 `YJ.device.isMb()/isPc()/mode()/onChange(cb)`，**断点统一 768px**，与 Tailwind `max-md:` 同源；用 `matchMedia('(max-width:767px)')` 实现，随 CSS 实时响应、永不脱节，不支持时回退 `innerWidth`。
- **常驻列表并入 isPc**：去掉 `profile.html` 独立 1024 断点（`isWide()` 方案被否——用户明确「不要幺蛾子」），常驻列表/双栏由 `isPc()`（≥768）统一决定；配套 CSS `max-lg:`（1024）全部拉齐 `max-md:`（768），消除「判 pc 却单列」中间态，符合 AGENTS.md「统一 max-md 单断点」。
- **断点翻转实时重渲染**：`races.html` 订阅 `YJ.device.onChange()`，pc/mb 翻转时用缓存 `lastR` 免请求重渲染当前马。

### 10.3 打磨迭代

1. 盘点散落判定：`races.isMb`（768）/ `profile` innerWidth（1024 两处）→ 收敛到 `YJ.device`。
2. 首版保留 `isWide()`（≥1024）当「布局决策」→ 用户拍板统一 → **删除 isWide/WIDE**，常驻列表并入 `isPc()`。
3. 断点拉齐：profile 双栏 6 处 + selector 常驻 2 处 `max-lg:` → `max-md:`，构建后复检 theme css 含新类、无 max-lg 残留。
4. 复现「桌面渲染后切手机仍 PC 表格」→ 加 `onChange` 免请求重渲染修复，PC/mb 双端切换实测通过。

### 10.4 最终落地

- **合并文件**：
  - `public/device.js`（新增）— 统一入口：`isMb()/isPc()/mode()/onChange()`，768px，matchMedia。
  - `pages/races.html` — `isMb()` 委托 `YJ.device.isMb()`；`lastR` 缓存 + `YJ.device.onChange` 断点翻转重渲染。
  - `pages/profile.html` — `persistent: YJ.device.isPc()`；滚动分支改 `isMb()`；双栏/常驻 CSS `max-lg:`→`max-md:`。
  - `public/selector.js` — 常驻列表断点 `max-lg:`→`max-md:`。
- **后续用法约定**：页面加 `<script src="../device.js"></script>`，分支写 `if (YJ.device.isPc()) {…} else {…}`；依赖渲染形态的功能在设备翻转时用 `YJ.device.onChange` 重渲染。

- **提交**：随本模块 commit（见 git log）。

### 12.2 选定与理由（思路）

- **独立与内嵌彻底解耦**：页面已有的 `EMBED` 分支天然隔离两条路径。独立模式新增 `initLibrary()` 全库加载：`YJ.selector.loadHorses(basic.json)` → 按 `races_file` 映射 → **16 并发池**拉取全部 276 个赛绩文件 → 内存聚合 `entries:[{h,r}]`（纯前端，不动后端与数据）。内嵌分支只多一行隐藏 `#filters`，其余 embed 逻辑零改动。
- **维度条（电商式）**：8 维横排——场地（中央/地方/海外）、跑道（草地/泥地/全天候）、距离（四档）、马场状态（良/稍重/重/不良）、级别、着顺、年份 + 竞马场**分三行**（中央 10 场 / 地方 7 场 / 海外统一一项）。筛选模型 `FLT` 每维是**数组**：同维度多选=OR，跨维度=AND；空数组=不限。
- **级别重定义**：单级 G1/G2/G3/Jpn1/Jpn2/Jpn3/L/OP + 聚合「重赏」（=G1-3+Jpn1-3，**单独占一行**）+ 班赛（1/2/3胜クラス）+ 新马/未胜利。

- **聚合项 tooltip**：距离档（短距离≤1400m…）、重赏、班赛、着外、未完走等「一个词含多个意思」的选项，chip 内只放简短标签，**悬停显示黑色小气泡**说明（`data-tip` + CSS `::after`），不占界面。
- **分页（前端内存分页）**：数据已全量在内存，卡顿根源是**一次性渲染全部 DOM**（716 场约 1 万+ 单元格）。故在筛选+排序之后切片渲染：`PG={page:1,size:100}`（可切 20/50/100/200），页码按钮式（首尾常显 + 当前页±2 + 省略号），筛选/清空/条数切换回第 1 页、页码越界自动修正，PC 表格与 mb 卡片同步分页。**虚拟滚动暂不做**（716 场分页足够，数据上万再考虑）。

- 无头 Chrome 实测（把 `dist/pages/races.html` 装进不同宽度 iframe）：

  | 场景 | 容器宽 | 表内留白 | 文本列 列宽/内容 | 数字列 |
  |---|---|---|---|---|
  | 24" | 1467px | 34.8% | 1.5–1.9× | 1.0–1.2× |
  | 27" | 2043px | 53.2% | 2.5–3.2× | **1.0–1.2×（一像素没变）** |

- 根因两条：① v5 只把留白喂给 7 个弹性文本列，14 个数字列恒卡最小宽 → 一边挤一边空；
  ② **分配只决定留白摆在哪，不改变留白总量**（总量 = 1 − 内容宽 ÷ 容器宽，由屏宽 ÷ 字号决定）。

### 23.2 选定与理由（思路）

- 四条候选（临时对比页 `tests/_scratch/colwidth/` 同屏并排实测）：
  A 只分配 / B 分配+升档到留白 ≤45% / **C 分配+升档到留白 ≤40%** / D 整页封顶 1560px 居中。
- **用户拍板 C**：27 寸留白 53.5% → 38.1%，且 24 寸及以下数值完全不变（五方案在 24 寸实测一致）。
- 分配规则（三阶段加权注水 `fill()`）：弹性文本列先吃（软上限 2.0×）→ 余量给数字列（软上限 1.5×）
  → 再有余量全表均分（保证表宽恒等于容器，右侧不留空条）。24 寸留白本就被弹性列吃光 → 数字列不参与，观感与 v5 一致。

### 23.3 打磨迭代

1. 升档判据从「分配后余量」改为「**表内留白占比**」——余量会被软上限吃掉，屏再宽也不一定触发升档；用户感知的「空不空」就是内容宽 ÷ 容器宽。
2. 档位度量口径对齐：把每列 8px 余量从「内容墨迹总宽」里扣掉，判据与肉眼一致（否则会少升一档）。
3. 量宽从 canvas 单量改为 **canvas 粗排 + DOM 探针精量**：canvas 量出的宽度比真实排版窄 3–4px/列，浏览器会自己从别的列偷偷挪宽度补上（实测 负磅 31→34、人气/着順 28→30），列宽不再完全由算法决定。改为：canvas 先按宽排序取前 5 个候选 → DOM 探针（继承 body 同一字体栈、指定档位字号、带缓存）精量，格式串与表头同样走 DOM 精量。
4. 容器量不到宽（隐藏/未布局）时退回最小档，避免误判成大屏放大字号。

### 23.4 最终落地

- **合并文件**：`pages/races.html`
  1. 列宽策略 v5 → v6：新增 `libLayout(fs, containerW)`（量最小宽 + 三阶段分配）、`fill()` 加权注水、`libVal()` 字段量宽表；
     删除 v5 的「只喂弹性列」分支；两遍渲染保留（先最小档量容器宽 → 选档 → 终渲）。
  2. 新增分档常量：`TIER_FS [11.5,12.5,13.5,14.5,15.5]`、`TIER_TH`（表头量宽字号）、`TIER_CLS`、`AIR_TARGET 0.40`、`CAP_TXT 2.0`、`CAP_NUM 1.5`。
  3. `<style>` 新增 `.yj-lib.fs125/fs135/fs145/fs155`（表体/表头字号、行高 py 7→8、着顺徽章 28→33px、等级徽章字号 padding）。
  4. `raceText()` 徽章额外宽随档位（padding 7→8、字号 +1 档）。
- **零改动**：内嵌模式（profile 下段）、mb 卡片、`i18n.js`、`data/`、其它页；`@media (max-width:1180px)` 窄屏档保留。
- **构建**：`npm run build` → `dist/`。

## 24. 比赛记录·等级徽章 L / OP 不可见修复（类名大小写）

### 24.1 现象

级别筛「L」「OP」时，赛事名后面本该有的金色 `L` 徽章、浅青绿 `OP` 徽章都看不到；G1/G2/G3 徽章正常。

### 24.2 原因

- `<style>`：底色由 `.yj-gl` / `.yj-gop` 提供，`.yj-grade` 只写 `color:#fff`（白字）。
- JS：等级→配色表 `G` 里写的是 `"L":"gL"`、`"OP":"gOP"`，渲染出来是 `class="yj-grade yj-gL"`。
- **HTML 的 class 选择器区分大小写** → `.yj-gl` 匹配不上 `yj-gL` → 没有底色 → **白字落在白卡片上 = 看不见**。
- 这是老 bug（v5 时代就在），只是模块 22 去掉赛事名里的 `(L)`/`(OP)` 文字尾缀后，等级信息只剩徽章一条路，才暴露出来。

### 24.3 修复

- `G` 取值统一改小写：`"L":"gl"`、`"OP":"gop"`，与 `.yj-gl` / `.yj-gop` 一一对应。
- 两处都补注释：**G 的取值必须与 `<style>` 里的 `.yj-g*` 类名完全同大小写（全小写）**，否则徽章无底色、白字不可见。

### 24.4 验证

无头 Chrome 点筛选片「级别 = L + OP」，读渲染后徽章的计算样式：

| 徽章 | class | background | color | 可见 |
|---|---|---|---|---|
| L | `yj-grade yj-gl` | `rgb(220,160,38)` 金 | `#fff` | ✅ |
| OP | `yj-grade yj-gop` | `rgba(10,167,160,.15)` 浅青绿 | `rgb(10,122,117)` | ✅ |

### 24.5 新增/修改等级徽章时的注意事项

三处名字必须完全一致（全小写）：

1. `G`（等级 → 类名后缀，如 `"GI":"g1"`）；
2. `<style>` 里的 `.yj-g1{background-color:…}`（写死色值属允许的「指定色块」）；
3. `GLABEL`（徽章显示文字，如 `"GI":"G1"`）。
